# 阅读任务
1. 由论文 2.2 节提到 "our network is based on the transformer architecture"可得LLaMA使用的是Transformer Decoder-only架构，且训练目标是预测下一个token。
   通过不断根据前文去预测之后的token，可以让模型去学习到语言的语法，语义等多种语言能力，从而成为生成文本的基础
3. 论文提到主要训练数据集来源于多个领域混合而成，都是开源数据集并且着重使用了已经被其他大模型使用过的数据源，其中CommonCrawl占训练集主体，整个训练集大概1.4万亿个token。
   **表：LLaMA 预训练数据配比（来源：LLaMA 论文 Table 1）**

| Dataset | Sampling prop. | Epochs | Disk size |
| :--- | :--- | :--- | :--- |
| CommonCrawl | 67.0% | 1.10 | 3.3 TB |
| C4 | 15.0% | 1.06 | 783 GB |
| Github | 4.5% | 0.64 | 328 GB |
| Wikipedia | 4.5% | 2.45 | 83 GB |
| Books | 4.5% | 2.23 | 85 GB |
| ArXiv | 2.5% | 1.06 | 92 GB |
| StackExchange | 2.0% | 1.03 | 78 GB |
由Hoffmann et al. (2022)的研究表明，在给定的计算预算下，用更多数据训练的较小模型，性能往往优于用较少数据训练的大模型，其中论文也提到推理成本也是模型评估的重要部分，更长时间训练的小模型虽然训练时会贵一些但是在推理时最终会更便宜。例如论文中提到70 亿参数模型的性能即使在训练了 1 万亿个 token 后仍在持续提升。
4. 
   - zero-shot：只给任务描述，不给示例
   - few-shot：给几个“示例 + 答案”，再给问题

- 例如这个自然问答任务，将真实用户的问题（分类，推理）转化成文本，通过zero—shot或few-shot然后通过自由生成任务或者多项选择任务让模型去续写之后的token，变相让模型完成了答案文本的生成任务，这个过程相较于微调，不会去修改模型参数。
5. 
  - Base Model就是预训练模型只能去生成后续的token，Instruct Model指令模型就是能够听懂·使用者提出的指令并直接给出答复，由第四题可知通过转化文本Base Model本来也有能够问答的能力，但由论文内容可得少量的微调就可以进一步提升模型的指令跟随能力。指令微调通过训练模型改变了模型参数，并且让模型具有直接回答问题的能力，且MMLU（大语言模型评测的基准）的性能有所提高。模型的架构不变，参数量不变
